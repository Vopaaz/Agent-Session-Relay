# Agent-Session-Relay v0.3.0

Ask a side question without handing off an unfinished review. Run `relay btw` before sending a
prompt to select a read-only turn; the following prompt returns to normal automatically. Use
`relay btw --cancel` to cancel the selection before submitting the prompt.

## Changes

- Btw preserves the reviewed checkpoint, staged approvals, and manual edits. It does not advance
  the main human-diff baseline, so the next normal turn sees accumulated human changes.
- Normal prompt hooks include the human-changed file list, with repository-relative paths encoded
  as JSON. Full patches remain available on demand through `relay agent diff human`. Btw omits the
  file list but keeps the same inspection command available, fixed at turn start.
- Btw instructions require read-only work. A small best-effort tool guard blocks known file writers
  and obvious shell writes. If writes still occur, Agent Stop saves them before restoring the entry
  workspace and complete index, including staged-only content and intent-to-add entries. Unchanged
  files are not rewritten. This is not an execution sandbox: unrelated ignored files and effects
  outside the repository are outside the restoration scope.
- Inspect saved output with `relay agent diff btw --turn N` or add `--staged` for the saved index
  delta. During a normal agent turn, `relay agent restore-btw N` applies the saved workspace delta
  as unstaged agent changes; `--staged` retrieves the index delta instead. Conflicting patches leave
  the workspace unchanged. Records survive suspend/resume and are deleted by finish/abort.
- Hook context now introduces Relay's role in human/agent review and describes the current turn,
  review guidance, and inspection commands without injecting full patches.

## Upgrading from v0.2.x

**Existing sessions are incompatible.** The metadata schema changes from 1 to 2, with no migration.
The new version rejects both active and suspended v0.2.x sessions without modifying their code or
saved review state. Do not upgrade Relay while those sessions are still in progress.

1. Using the old version, finish or abort every session in each affected worktree. Resume suspended
   sessions first. If an interrupted operation requires recovery, resolve it with the old version.
2. Confirm that `relay list --json` prints `[]`. Old finish/abort leaves an empty schema-1 state file,
   which v0.3.0 also rejects. Run the following once in each affected worktree to remove only that
   empty file:

   ```bash
   python3 - <<'PY'
   import json
   from pathlib import Path
   import subprocess

   git_dir = Path(subprocess.check_output(
       ["git", "rev-parse", "--absolute-git-dir"], text=True
   ).strip())
   directory = git_dir / "agent-session-relay"
   state = directory / "state.json"
   if (directory / "transaction.json").exists():
       raise SystemExit("Use the old Relay version to recover the interrupted operation first.")
   if state.exists():
       if json.loads(state.read_text()) != {"schema": 1, "active": None, "sessions": {}}:
           raise SystemExit("State is not empty v0.2.x metadata; no file was removed.")
       state.unlink()
       print("Removed empty v0.2.x state.json.")
   PY
   ```

3. Upgrade your installation, for example with `pipx upgrade agent-session-relay`, then verify
   `relay --version` reports `0.3.0`. Existing Kiro hook configuration continues to invoke the same
   CLI entry points. New sessions use schema 2.

The empty-file cleanup does not migrate sessions or remove code, result branches, or abort recovery
branches.
