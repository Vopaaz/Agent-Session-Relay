# Agent-Session-Relay v0.8.2

Improves `relay start --repo` errors so an invalid member path identifies the original argument
and its cause when starting a multi-repository session from a non-Git parent directory.

## Clearer repository path errors

For example, `relay start --repo r1 --repo r2_typo` now reports:

```text
relay: Invalid --repo 'r2_typo': directory does not exist
```

- Missing paths and paths that are not directories have distinct errors.
- Non-Git directories and bare repositories report the offending `--repo` argument and the
  underlying Git error. Git initialization also retains useful diagnostics such as permission
  errors and dubious ownership instead of replacing them with only a generic working-tree hint.
- Failed path validation leaves session state and Relay refs untouched. Correcting the path
  allows the workspace session to start normally.

Regression tests cover missing paths, ordinary files, non-Git directories, bare repositories,
retained permission and ownership diagnostics, and successful startup after correcting paths.

## Compatibility and upgrading

The package version is `0.8.2` and the Git tag is `v0.8.2`. Per-worktree metadata remains schema 2,
and workspace metadata remains schema 1. Session behavior is unchanged. Existing sessions need
no migration, and hooks do not need to be reinstalled.

Upgrade with `pipx upgrade agent-session-relay` and verify that `relay --version` reports `0.8.2`.
For standalone installations, replace `relay.pyz` with the new archive. Users upgrading from
v0.2.x must first follow the [v0.3.0 cleanup instructions](v0.3.0.md#upgrading-from-v02x).

Maintainers can follow the [release instructions](../../CONTRIBUTING.md#releases). The tag workflow
creates a draft GitHub release; PyPI upload and publication of the draft remain explicit steps.
