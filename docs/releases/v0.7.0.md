# Agent-Session-Relay v0.7.0

One Relay session can now coordinate a feature across multiple repositories. Prompt hooks include
per-file change counts and introduce the full protocol once per conversation, followed by brief
reminders.

## Multi-repository sessions

Start from the repositories' common parent:

```bash
relay start --repo ./cdk --repo ./service --repo ./integration-tests -m "Implement the feature"
```

- Hooks and commands discover the same session from the parent, any selected repository, or its
  subdirectories. Existing hooks must already be loaded; no environment variable is needed.
- Review each repository through its own Git staging UI. Prompt Submit, Stop, btw, suspend/resume,
  and finish/abort operate on the shared session. Finish requires all members to be reviewed and
  creates one result commit per changed repository.
- Agent status and semantic diffs cover all members by default. Output paths are workspace-relative;
  `--repo <name>` selects a member, while path filters after `--` remain relative to cwd.
  Use `relay agent git --repo <name> <args...>` for a member's history queries.
- Group transactions coordinate rollback and recovery across members. Unselected repositories
  remain outside the session. See [workspace sessions](../workspaces.md) for details.

## Smaller hook context

- The first interaction in each harness conversation within a Relay session receives the full
  protocol. Later interactions retain the active-session marker, Git and Relay control restrictions,
  and the unstaged-edit or read-only reminder. Suspend/resume and moving between member directories
  do not repeat the introduction. A new conversation receives it again. Without a harness
  `session_id`, prompts share one introduction per Relay session.
- Each new editing turn includes complete per-file added/deleted line counts, separately labeled
  `Approved this turn` and `Human edits at turn start`. Binary changes are marked `binary`; unusual
  filenames are JSON-quoted. Full patches remain available on demand.
- Continuing an open turn gets a one-sentence reminder that reviewed/human diffs refer to the
  original handoff, without repeating old stats. Btw turns retain read-only reminders and semantic
  queries without injecting change stats. Editing turns no longer introduce a "normal turn" label.

## Compatibility and upgrading

Per-worktree metadata remains schema 2. Existing v0.3.0–v0.6.0 sessions need no migration, and Kiro
hook entry points are unchanged. Multi-repository configuration uses a separate schema 1 file at
the common parent's `.relay/state.json`. Finish or abort independent sessions before enrolling their
repositories in a workspace session. Workspace sessions require this version or later.

Hook text now uses per-file line counts instead of JSON path arrays and shorter reminders after
the introduction. Integrations that parse hook prose should use `relay agent status` or semantic
diff commands instead. Their single-repository behavior is unchanged; workspace status adds member
information and workspace diffs prefix paths with the repository name.

Upgrade with `pipx upgrade agent-session-relay` and verify that `relay --version` reports `0.7.0`.
For standalone installations, replace `relay.pyz` with the new archive. Users upgrading from v0.2.x
must first follow the [v0.3.0 cleanup instructions](v0.3.0.md#upgrading-from-v02x).
