# Agent-Session-Relay v0.6.0

Relay now distinguishes a continued agent turn from a new human-to-agent handoff and gives humans
an explicit command to close a turn after manually interrupting the agent. Read-only btw turns
keep emergency snapshots outside Relay's review state, with no dedicated recovery commands.

## Manually interrupted agent turns

If Kiro's Agent Stop hook completes after an interruption, Relay returns to the human phase as
usual. If Stop does not run, the existing agent turn remains open.

- Submitting another prompt in the same conversation continues that open turn. Hook context now
  says that no new handoff occurred and that review and human-edit context still refers to the
  turn's original handoff. It does not repeat the original approval and human-edit path notices.
  The turn's mode and semantic diff baselines stay unchanged; submitting a prompt does not seal
  any intervening staged changes. A different known conversation still cannot take over the turn.
- After manually stopping the agent, run `relay end-interrupted-agent-turn` before editing,
  staging, or discarding changes. It performs the same cleanup as Agent Stop and returns Relay
  to the human phase. A normal turn's code remains in the workspace as unstaged proposals; a
  btw turn uses the backup and restoration behavior described below. The next prompt creates
  a new handoff that captures the subsequent human review and edits.
- The command requires an active session with an open agent turn. It rejects inactive,
  suspended, and human-phase sessions, including repeated calls after a successful close.
  Kiro's tool guard blocks agent invocations. Failures use the existing transaction rollback.

The command does not stop the agent process or detect how it ended. It cannot reconstruct the
boundary between agent and human edits if manual review already happened before it ran.
`relay recover` remains the command for interrupted Relay transactions, not missing Stop hooks.

## Simpler read-only btw turns

- The only dedicated btw commands are `relay btw` and `relay btw --cancel`.
- If a btw turn changes captured project files or staging, Stop saves emergency Git snapshots
  before restoring the workspace and complete index from that turn's original handoff. The
  immediate notice includes the relevant snapshot commit IDs and confirms the restoration.
  A btw turn with no changes needs no emergency output snapshot or notice.
- Emergency output is excluded from review state, semantic diffs, status, and later handoffs.
  If needed, use generic read-only `relay agent git` queries to inspect the underlying snapshots.
- Suspend/resume preserves the snapshots. Finish/abort removes their session refs along with
  the other session refs; unreferenced Git objects are subsequently eligible for Git GC.

Restoration still covers captured project files and staging, not unrelated ignored files or
effects outside the repository. The btw tool guard remains a workflow aid rather than an
execution sandbox.

## Compatibility and upgrading

**Removed commands and options:**

- `relay agent restore-btw N`, including its `--staged` variant.
- `relay agent diff btw --turn N`, including its `--staged` variant.
- The `--turn` and `--staged` options on `relay agent diff`.

**Status JSON:** `btw_recoveries` has been removed from both `relay agent status` and
`relay status --json`. Update scripts that consume this field or call the removed commands.
The active agent status response is now:

```json
{
  "active": true,
  "phase": "agent",
  "turn": 2,
  "turn_kind": "normal",
  "session_changes": true,
  "pending_changes": false,
  "provenance": {"available": true, "newly_reviewed": true, "human_edits": false}
}
```

Session metadata remains schema 2; existing v0.3.0–v0.5.0 sessions need no migration. Existing
btw snapshots remain available through generic Git inspection until session cleanup, but their
old recovery records no longer appear in status or handoff context. Kiro hook entry points are
unchanged, so hook configuration does not need to be reinstalled.

Upgrade with `pipx upgrade agent-session-relay` and check that `relay --version` reports `0.6.0`.
For standalone installations, replace `relay.pyz` with the new archive. Subsequent prompt hooks
inject the updated guidance.

Users upgrading from v0.2.x must first follow the session cleanup instructions in the
[v0.3.0 release notes](v0.3.0.md#upgrading-from-v02x).
