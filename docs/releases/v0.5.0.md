# Agent-Session-Relay v0.5.0

Agents can inspect the whole session without losing sight of approved work. Use
`relay agent diff session` for the current net changes since the immutable session base,
and `--stat` on any diff for a compact change summary:

```bash
relay agent diff session --stat
relay agent diff session --name-only
relay agent diff session -- src/
relay agent diff pending --stat
```

## Changes

- The new `session` view compares the session base to the live workspace, including approved
  changes, pending proposals, and new project files. It includes both human and agent work;
  reverted changes cancel out. Sealing approvals does not change the view. Existing `reviewed`
  and `human` views remain fixed at turn entry, while `pending` remains relative to the current
  reviewed checkpoint.
- Every diff, including saved btw workspace/index diffs, supports `--stat` with literal path
  filtering. `--stat` and `--name-only` are alternative output formats. Empty diffs still produce
  no output and exit successfully; unsupported options still fail explicitly on stderr.
- Normal-turn hooks announce approvals only when they were sealed at that handoff. The notice
  lists affected paths separately from human edits and explains that other hunks in those files
  may still be pending. Duplicate hooks preserve the same notice; btw does not seal approvals.
- Hook guidance calls human workspace changes "edits", without implying a separate discard or
  rejection state. It introduces the session view and statistics without advertising the optional
  `-z` flag; `--name-only -z` remains available to scripts.
- `relay agent status` now focuses on the current phase and turn, live session/pending changes,
  turn provenance, and saved btw recovery commands. Full human diagnostics remain available
  through `relay status --json`.
- English/Chinese documentation and CLI help describe the new views and status contract.

## Agent status compatibility

**The agent JSON response has changed.** For an active session, it contains:

```json
{
  "active": true,
  "phase": "agent",
  "turn": 2,
  "turn_kind": "normal",
  "session_changes": true,
  "pending_changes": false,
  "provenance": {"available": true, "newly_reviewed": true, "human_edits": false},
  "btw_recoveries": []
}
```

`session_changes` compares the live workspace to the session base. It can remain true when all
changes are approved and `pending_changes` becomes false. `provenance` still describes the latest
turn entry and stays fixed during the turn. Without an active session, the response is only
`{"active": false}`, including when sessions are suspended.

The agent response no longer exposes `session`, `message`, `lifecycle`, `next_turn`, `base_commit`,
`origin`, `reviewed_checkpoint`, `staged_approvals`, `unstaged_changes`, `inspection_commands`,
`diff_options`, or inactive `suspended_sessions`. Scripts that need these human diagnostic fields
should use `relay status --json`. Agents should use `diff session` for a session-wide view and
`provenance.newly_reviewed` to detect approvals sealed at the latest handoff.

## Upgrading from v0.3.0 or v0.4.0

Session metadata remains schema 2; existing sessions need no migration. Kiro hook configuration
uses the same CLI entry points and does not need to be reinstalled.

Upgrade your installation, for example with `pipx upgrade agent-session-relay`, and check that
`relay --version` reports `0.5.0`. For standalone installations, replace `relay.pyz` with the new
archive. Subsequent prompt hooks inject the updated guidance.

Users upgrading from v0.2.x must first follow the session cleanup instructions in the
[v0.3.0 release notes](v0.3.0.md).
