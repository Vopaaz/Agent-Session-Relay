# Agent-Session-Relay v0.7.1

Relay now preserves Git's detection of rapid, same-size edits when copying or restoring the index,
fixing intermittent missing human-change context after read-only btw turns.
Workspace finish now consistently prefers per-repository commit messages and requests a shared
message only when a member needs one. New Kiro conversations joining an existing Relay session
receive a short reminder to inspect the cumulative changes before making edits.

## Reliable snapshots of rapid edits

- Temporary index copies preserve the original index timestamp. Previously, a new timestamp could
  let Git's cached file information hide edits made within the same timestamp resolution without
  changing the file's size, producing a workspace snapshot with outdated contents.
- Restoring a saved index also retains conservative content checks while preserving its raw bytes,
  staged contents, and intent-to-add entries. This covers btw restoration, resume, and rollback.
- Human edits made before a read-only btw turn remain visible in the next normal turn's context.
  Regression tests reproduce the timestamp collision directly, including full and split indexes,
  without depending on test timing.

## Workspace commit messages

- A repository's message set with `relay message --repo <name>` always takes priority at finish.
- If every member has its own message, `relay finish` no longer requires a shared message or opens
  an editor, even when no shared message has ever been saved.
- Members without their own message use the shared message. If it is missing, finish opens one
  editor to supply it for those members, preserving all per-repository messages.
- `relay finish -m "Shared description"` replaces only the shared message for that finish. In
  v0.7.0, it also overrode per-repository messages; those overrides now remain in effect. To change
  a repository's own message, use `relay message --repo <name> -m "Repository description"`.

The `relay message` commands retain their existing behavior. Review requirements, group rollback,
and result-commit ancestry are unchanged. Members without net changes still return to their origin
without creating empty commits.

## New-conversation guidance

When a Kiro conversation first joins a Relay session with prior turns, its full introduction now
includes:

> You are taking over a Relay session with prior turns. The current workspace may contain earlier
> human and agent changes. Before making changes, consider running `relay agent diff session --stat`
> to understand the cumulative changes since this Relay session began.

This applies to both single-repository and multi-repository sessions. Existing conversation
identification and prompt-shortening rules remain unchanged: the first Relay turn has no takeover
notice, later interactions in an already introduced conversation stay brief, and duplicate hooks
do not repeat the notice. A different known conversation still cannot take over an open agent turn.

## Compatibility and upgrading

Per-worktree metadata remains schema 2, and workspace metadata remains schema 1. Existing sessions
need no migration, and hook configuration does not need to be reinstalled. Single-repository
`finish -m` behavior is unchanged.

Upgrade with `pipx upgrade agent-session-relay` and verify that `relay --version` reports `0.7.1`.
For standalone installations, replace `relay.pyz` with the new archive. Users upgrading from v0.2.x
must first follow the [v0.3.0 cleanup instructions](v0.3.0.md#upgrading-from-v02x).
